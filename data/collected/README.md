Schema for all files: `timestamp, cpu_percent, memory_percent, request_rate, post_scaling`
(`metrics_dummy_backup.csv` has no `post_scaling` column).

| File | Rows | Kind | Notes |
|---|---:|---|---|
| `metrics.csv` | 90,000 | **synthetic** | Generated by `model/generate_realistic_data.py`. Exactly 30 s steps from 2026-09-19 00:00:00 to 2026-10-20; 1,800 rows have `post_scaling=True`. This is what `train.py`, `prophet_model.py`, `evaluate.py` and the tests read. Not measured from containers. **FROZEN — never append live rows to it** (see below). |
| `metrics_live.csv` | grows | real | The collector appends here (`monitoring/storage.csv_path()`); the real loop reads its last 10 rows. Override with the `PROXIMASCALE_LIVE_METRICS_PATH` env var. |
| `metrics_real_dev.csv` | 121 | real | Collected from the Docker app 2026-09-12 to 09-14, ~63 s between rows (not 30 s). The only genuine container data. |
| `metrics_real_82lines.csv` | 81 | real | Earlier snapshot of the same collection. |
| `metrics_20k.csv` | 20,000 | synthetic (inferred) | 30 s steps from 2024-01-15. |
| `metrics_1.csv` | 2,000 | synthetic (inferred) | Starts 2024-01-15 with one large timestamp gap. |
| `metrics_dummy_backup.csv` | 2,000 | synthetic (inferred) | Backup of the Semester-1 dummy data; no `post_scaling` column. |

"Synthetic" here is inferred from the data (perfectly regular timestamps,
round row counts, generator scripts in the repo). Results from the synthetic
files show the pipeline is coherent; they are not evidence about real traffic.

Running `python -m monitoring.collector` appends to `metrics_live.csv` — never to
the frozen training `metrics.csv`. Earlier runs appended live idle rows directly
after the synthetic history, so every model window crossed a synthetic→live
discontinuity (predicted ~57% CPU while the container idled at 0.02%) and idle
jitter tripped false "anomaly" scale-ups. Retraining still reads `metrics.csv`.
To collect a clean real dataset from scratch, just delete `metrics_live.csv`.
